# SPACE

SPACE is a mobile web application for convention and event planning.  
The project uses C++ for the shared application/simulation logic, OpenGL/WebGL for rendering, and Emscripten for the web build.

---

# Running the Project

## Desktop

1. Clone the repository.
2. Open PowerShell in the project root.
3. Run:

```powershell
.\script_build_and_run.bat
```

This will configure, build, and run the desktop version.

The generated Visual Studio project can be found inside:

```text
build_desktop/
```

---

## Web / WebGL Build

The project does **not** store a hardcoded Emscripten installation path.
Each developer configures their own local `EMSDK_HOME` environment variable.

### First-Time Setup

Install the Emscripten SDK on your computer.

Then set `EMSDK_HOME` to the folder where your Emscripten SDK is installed.

Example:

```powershell
setx EMSDK_HOME "C:\emsdk"

### Build

From the project root:

```powershell
.\build_web.bat
```

### Run

After the build succeeds:

```powershell
cd web
python -m http.server 8080
```

Then open:

```text
http://localhost:8080
```

Do not open the generated HTML directly using `file://`.

# Project Architecture

```text
DesktopShell / WebShell
          ↓
       CoreAPI
          ↓
      Application
      /    |     \
 Scene3D SceneHUD Future ECS
      \    |     /
         Renderer
             ↓
       OpenGL / WebGL
```

### Platform Shell

```text
platform/
├── desktop/
└── web/
```

Handles platform-specific behaviour such as:

- Window/browser setup
- Input
- Resize
- Frame loop
- Fixed timestep

Do not put simulation or application logic here.

### Core API

```text
source/core/CoreAPI.*
```

Shared interface used by both Desktop and Web.

### Application

```text
source/app/Application.*
```

Coordinates application systems, scenes, input routing, and future ECS integration.

### Renderer

```text
source/render/
```

Rendering and graphics-related code only.

# Files to Avoid Editing Without Coordination

These files affect the overall architecture and may cause merge conflicts:

```text
CMakeLists.txt

source/core/CoreAPI.h
source/core/CoreAPI.cpp

source/app/Application.h
source/app/Application.cpp

source/render/Renderer.h
source/render/Renderer.cpp

platform/desktop/DesktopShell.cpp
platform/web/WebShell.cpp
```

If you need to modify one of these files, inform the team first.

# Where New Code Should Go

| Code | Folder |
|---|---|
| ECS / core systems | `source/core/` |
| Crowd simulation / pathfinding | `source/sim/` |
| Application / venue editor | `source/app/` |
| Rendering / shaders / graphics | `source/render/` |
| UI / HUD | `source/ui/` |
| Networking / backend communication | `source/services/` |
| Desktop-specific code | `platform/desktop/` |
| Web-specific code | `platform/web/` |
| Tests | `tests/` |
| Development tools | `tools/` |

# Visual Studio Filters

The purple folders in Visual Studio are generated by CMake.

Do not manually create or reorganise Visual Studio filters.

Instead, create the actual folder/file in the repository.

For example:

```text
source/sim/pathfinding/AStar.cpp
```

will automatically appear as:

```text
Source
└── sim
    └── pathfinding
        └── AStar.cpp
```

# Git Workflow

Create a branch for each task:

```powershell
git switch main
git pull origin main
git switch -c feature/<task-name>
```

Example:

```powershell
git switch -c feature/ecs
```

Before opening a Pull Request, make sure both the Desktop and Web builds still work.
